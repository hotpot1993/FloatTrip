# amap-rest-call-channel Specification

## Purpose

把后端所有高德 REST 调用收敛到唯一入口，使额度预占、并发约束、失败分类与结果缓存对每一条调用路径一致生效。本能力定义"请求怎么发出去"，额度本身如何计量由 `amap-quota-guard` 定义。

## ADDED Requirements

### Requirement: 唯一的高德 REST 调用通道

后端 SHALL 只通过一个调用通道发出高德 REST 请求。所有既有出口——包括由同步路由直接发起的请求，以及当前绕过公共 HTTP 层的内联请求——SHALL 改经该通道。

通道 SHALL 按固定顺序执行：判定失败类别、预占额度、获取并发槽位、发出请求。预占额度 MUST 早于任何网络动作，包括早于等待并发槽位。

#### Scenario: 同步路由取得并发约束
- **WHEN** 手动编辑相关的同步路由发起高德请求
- **THEN** 该请求与规划任务内的请求共享同一个并发约束，而不是绕过它

#### Scenario: 等待槽位期间额度被占走
- **WHEN** 一个请求已通过预占但在等待并发槽位期间额度被其它请求用尽
- **THEN** 该请求不受影响地继续（额度已在等待之前占定），且后续请求按剩余额度被拒绝

### Requirement: 高德失败按语义分类处理

系统 SHALL 依据高德响应中的 `infocode` 与 `info` 判定失败类别，分为：

- **配额类**：继续请求没有意义，SHALL 立即失败且 MUST NOT 重试；
- **限流类**：降速后可恢复，SHALL 退避后重试；
- **其它**：沿用既有失败语义，行为 MUST NOT 比变更前更差。

配额类失败 SHALL 被识别为"额度已用尽"并携带可区分的公开错误码，使上层无需知道失败来自本地预占还是高德响应。

未识别的响应与网络异常 SHALL 保持既有语义，不得被误判为配额耗尽。

#### Scenario: 配额类失败立即失败且不重试
- **WHEN** 高德返回配额类失败
- **THEN** 通道立即抛出配额耗尽异常，不进行任何退避重试，也不产生额外请求

#### Scenario: 月配额超限返回未文档化的错误码
- **WHEN** 高德以官方错误码表未收录的 `infocode` 表示月配额已用尽
- **THEN** 该次失败仍以未知错误的既有语义上报，不产生重试放大，也不被静默当作成功

#### Scenario: 限流类退避重试
- **WHEN** 高德返回限流类失败
- **THEN** 通道退避后重试，且每次重试各自预占额度

#### Scenario: IP 访问受限不可自动恢复
- **WHEN** 高德返回 IP 访问超限
- **THEN** 系统以区别于"额度用尽"的错误码与文案上报，说明需要人工解封，而不是让用户等待额度重置

#### Scenario: 密钥失效
- **WHEN** 高德返回无效密钥或服务未开通
- **THEN** 系统以上报密钥不可用收场，且不重试

### Requirement: 高德结果缓存按服务组额度复用

系统 SHALL 缓存可复用且成本较高的高德结果，使缓存命中不产生网络请求、因而不消耗任何池的额度。

缓存键 SHALL 包含所有影响该结果的请求参数。失败响应 MUST NOT 写入缓存。

#### Scenario: 缓存命中不消耗额度
- **WHEN** 一次周边搜索命中缓存
- **THEN** 系统直接返回缓存结果，不预占额度、不发出请求

#### Scenario: 参数不同不得复用
- **WHEN** 两次周边搜索使用相同的中心坐标但不同的搜索半径或类型
- **THEN** 第二次为缓存未命中并真实发起请求，而不是返回第一次的结果

#### Scenario: 失败结果不被缓存
- **WHEN** 高德返回失败响应
- **THEN** 该结果不写入缓存，后续请求仍会真实发起
